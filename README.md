# OFF/SET — Distorted Poster Map

브라우저 안에서 포스터를 개별 요소로 나누고, 흔들림으로 물리적 변형을 만든 뒤 저장하는 웹 앱입니다. 별도 서버나 API 키 없이 실행됩니다.

## 실행

Node.js 24와 npm을 사용합니다. PDF 처리 라이브러리는 Node.js 22.13 이상을 요구하며, 배포 시에는 검증한 Node.js 24를 사용하도록 지정했습니다.

```sh
npm ci --cache /workspace/.cache/npm
npm run dev
```

다른 환경에서는 `--cache` 옵션을 생략해도 됩니다. 개발 서버 기본 포트는 5173입니다.

```sh
npm run build
npm test
npm run test:browser
npm run preview
```

브라우저 통합 검사는 시스템 Chromium(`/usr/bin/chromium`)을 사용합니다. 다른 위치의 브라우저는 `CHROMIUM_PATH`로 지정할 수 있습니다. 통합 검사에서 개발 서버를 별도 포트(4175)로 시작하고 종료하며, PNG/JPG 업로드, 다중 페이지 PDF의 텍스트 분리, 물리 효과, 좌표, 저장 파일, 모바일 화면을 확인합니다.

빌드된 결과물은 `npm run build` 후 `SMOKE_PRODUCTION=1 npm run test:browser`로 같은 기능을 검증합니다.

## Vercel 배포

Vercel 프로젝트에 `yeonjoo-kim/DistortedPosterMap` 저장소의 `main` 브랜치를 연결합니다. 루트 디렉터리는 저장소 루트이며, 프레임워크는 Vite, 빌드 명령은 `npm run build`, 출력 디렉터리는 `dist`입니다. 이 설정은 `vercel.json`에 저장되어 있습니다. API 키나 환경 변수는 필요하지 않습니다. `main` 브랜치에 새 커밋을 올리면 Vercel에서 자동 배포합니다.

## 동작

- PDF, JPG, PNG 업로드(최대 50MB), PDF 페이지 선택 및 요소 분리
- 덜 마른 점토처럼 반응하는 단일 재료: 중력, 부드러운 휨과 지그재그 변위, 충돌 압축·복원, 강한 충돌의 삼각 파편 생성
- 가속도 또는 카메라의 상대 움직임 강도로만 재료 반응을 결정합니다. 효과 선택, 민감도·중력·반발력 조절은 없습니다.
- Web Audio 기반 악기: 약한 움직임은 부드러운 저음, 강한 움직임은 높은 배음·노이즈·짧은 충돌음으로 변화합니다. 소리 시작/음소거, 일시정지 시 무음을 지원합니다.
- 요소별 현재·원래 좌표, 이동량, 회전, 눌림, 변형량, 경로와 변형 꼭짓점 JSON 저장
- PNG / JPG / 이미지 기반 PDF 출력(1×–3×), 원본 비교, 초기화 및 일시정지

## 노트북의 실제 움직임 입력

### 가속도 센서

HTTPS 또는 localhost에서 `DeviceMotionEvent`를 사용합니다. Safari 등에서 요구하는 센서 권한은 사용자가 연결 버튼을 누를 때 요청합니다. 센서 API의 존재만으로 연결 성공을 표시하지 않습니다. 두 번 이상의 유효한 가속도 데이터를 받아야 데이터 수신 상태로 표시하며, 값이 제공되지 않거나 신호가 끊기면 이를 구분해 표시합니다. 중력을 제외한 가속도가 있으면 우선 사용하고, 중력 포함 데이터만 있으면 저주파 중력 성분을 제거합니다.

**2020년형 M1 MacBook Pro에서 웹 브라우저에 가속도가 제공된다고 보장할 수 없습니다.** 이 클라우드에서는 사용자 맥북 하드웨어를 직접 검사할 수 없습니다. 실제 기기에서 센서 확인을 실행해 데이터 제공 여부를 확인해야 합니다. 브라우저에 센서 값이 노출되지 않는 경우 JS만으로 가속도 센서를 강제로 읽을 수 없습니다.

### 내장 카메라를 통한 상대 움직임 추정

센서 값이 없는 노트북을 위해 `getUserMedia` 카메라 입력과 광학 흐름 기반 움직임 추정을 구현했습니다. **물리 가속도 실측과 다른 방식**입니다. 고정된 배경에 대해 노트북과 카메라를 움직이면 화면 전반의 일관된 이동을 분석하여 재료·소리를 구동합니다. 충분한 조명과 무늬가 있는 정지한 배경이 필요합니다. 작은 전경의 움직임, 추적 특징 부족과 일관성 없는 움직임은 억제하지만, 사람이 화면 대부분을 차지하거나 배경 자체가 움직이면 노트북 움직임으로 오인할 수 있습니다. 검은 화면이나 단색 벽에서는 신뢰도가 떨어집니다. 물리 이동량이나 m/s²를 카메라에서 산출한다고 주장하지 않으며, px/s와 추적 신뢰도를 표시합니다.

카메라 권한은 버튼 클릭 시 브라우저가 요청합니다. **마이크는 요청하지 않으며**, 영상은 기기 메모리 안에서만 분석하고 저장·전송하지 않습니다. 감지 중지·다른 입력으로 전환·탭 이탈·컴포넌트 해제 시 카메라 트랙을 중지합니다. 권한 거부, 카메라 부재, 불안정한 추적을 화면에 표시합니다.

입력 테스트 버튼, Space 및 드래그는 테스트용 입력으로 별도 표시합니다. 실제 노트북 감지에 성공한 것으로 표시하지 않습니다.

## M1 맥북에서 확인하는 순서

1. Vercel 주소를 Safari 또는 Chrome의 독립된 탭에서 엽니다.
2. **카메라로 움직임 감지**를 누르고 브라우저와 macOS의 카메라 권한을 허용합니다. 영상에 무늬가 있는 정지한 배경이 넓게 보이도록 합니다.
3. 노트북을 조금 움직였을 때 **CAMERA ESTIMATE**의 px/s와 추적 신뢰도가 반응하는지 확인합니다. 주변 사람·배경 자체가 움직이는 상황은 피합니다.
4. **연주 소리**가 켜져 있는지 확인합니다. 작은 움직임에서는 부드러운 음, 큰 움직임에서는 날카로운 음색과 함께 더 큰 변형이 나타납니다.
5. 센서를 직접 확인하려면 **가속도 센서로 연주**를 누릅니다. 데이터 미제공 상태가 나오면 이 브라우저에서 실제 가속도를 읽을 수 없는 것이므로 카메라 추정을 사용합니다.

## 검증 범위

단위 검사는 픽셀 요소 분리, 연속 재료 반응, 충돌 압축과 복원, 센서 무응답·수신·해제, 정지/이동/전경 변화의 카메라 분석, 강도별 음색 함수를 검증합니다. 브라우저 검사는 **합성 가속도 이벤트**와 **캔버스에서 만든 가짜 카메라 스트림**을 실제 입력 처리 코드에 연결하여 재료·소리를 검증합니다. Web Audio의 실제 출력 파형과 주파수 분포도 검사합니다. 이는 실제 M1 맥북 하드웨어를 흔들어 시험한 결과가 아닙니다.

## 요소 분리와 저장 범위

이미지 분리는 컴퓨터 비전의 픽셀 연결 영역을 사용하며 의미 단위 사물 인식이나 OCR 모델은 포함하지 않습니다. 살아 있는 텍스트를 포함한 PDF 및 단색 배경의 그래픽 포스터에서 가장 잘 작동합니다. 복잡한 배경이나 겹친 요소는 하나로 합쳐질 수 있습니다. 분리되지 않은 픽셀은 배경에 남겨 이미지가 사라지지 않도록 합니다. 투명 PNG의 투명 배경은 추정 배경색으로 채웁니다. 긴 변을 최대 1,200px로 분석하므로 2×·3× 출력은 확대 출력이며 원본 벡터 품질 복원을 뜻하지 않습니다. PDF 텍스트는 텍스트 영역별로 분리하고 그 외 벡터는 렌더링한 픽셀을 분석합니다. 회전된 PDF 텍스트나 복잡한 레이아웃은 분리 정확도가 낮을 수 있습니다.

파일은 메모리에서 처리되며 서버에 업로드되지 않습니다. 페이지 새로고침 시 작업은 초기화됩니다. 외부 폰트가 차단되어도 시스템 폰트로 작동합니다.
